# 安全与隐私边界

当前版本面向单实例本地或受控内网使用。这份说明是工程边界，不是已经完成的第三方安全认证或合规声明。

## 密钥和配置

- API key、模型资源标识和自定义请求头只通过环境变量或未跟踪的 `.env` 文件注入；提交前检查 `git status` 和差异。
- 日志、截图、浏览器录屏和 issue 中不要粘贴 cookie、Authorization header、完整模型请求或用户研究原文。
- `QUNXUE_RUNTIME_MODE=mock` 不需要密钥；看到 mock/preview 时不能对外宣称已连接真实模型或已审核知识。
- 跨源部署必须明确设置允许的前端来源。不要把 `*` 与带 cookie 的认证一起使用。

## 数据和删除

研究任务、会话和知识发布默认写入本地 SQLite。使用者应当在部署前确定数据库目录权限、备份周期、保留期限和谁可以读取文件。产品中的“删除研究”是不可逆操作；备份副本仍需按部署方的数据政策处理。

## 运行和暴露面

`make dev-api` 使用 Uvicorn reload，适合开发，不应直接暴露到公网。公网部署至少需要 TLS、反向代理、受支持的数据库、密钥管理、速率限制、访问日志脱敏、备份与恢复演练，并由部署者进行独立安全评估。

## 报告问题

不要在公开 issue 中提交漏洞复现中的秘密或个人研究内容。先通过仓库维护者约定的私下渠道报告，说明受影响版本、复现步骤、影响范围和临时缓解措施；若没有私下渠道，应先暂停公开部署并由项目负责人建立一个。
