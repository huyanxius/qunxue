# 学术前沿：时期分析与研究日历

## 本轮交付范围
用户于 2026-10-02 明确暂缓自动更新功能。本轮集中完成已采集资料的清洗、可复算的时期分析、日期首页、趋势与研究日历，以及本地 UI 验收后的代码收尾。定时抓取、自动入库和知识自动发布不在本轮交付内。现有更新建议领域代码保留为未启用基础，不接定时任务或自动发布。

## 使用流程
研究者先选择时期，阅读重要议题变化；进入议题查看研究证据、方法与观点分歧；沿引用打开材料；将有价值的新证据提交为已有知识的更新建议。教师审核后形成新知识版本，保留修改前后和证据链。

## 当前增量代码
- `periods.py`：保留日/月/年精度的日期区间，在完整、同来源的两个时期计算主题份额差。缺覆盖、记录版本矛盾、空分母分别阻止该来源参与比较；未结束时期不作升降比较。当前输出为测量结果，不自动命名为理论转向。
- `calendar.py`：按独立研究去重的发表日历；月份级材料单独展示，不塞入月初。已撤回、未来和日期矛盾材料不进入日热力图。
- `updates.py`：补充、新主题、分歧、修订四类建议，固定知识目标版本和证据版本；重复建议具有稳定身份。审核时版本变化或证据撤回使建议失效。领域审核通过不等于已经发布。
- `/api/frontier/calendar`：已添加独立读接口及生成 SDK；其余时期分析与更新建议尚待持久化和应用层集成。

## 数据与推理边界
发布时间、采集时间和更新发现时间分别保存。来源范围与抓取覆盖始终保留机器可查证据。网页上的“近期变化”按发表时期组织；主题热度、学术价值与知识更新必要性分别计算。计量变化必须再经原文证据解释，才能成为面向用户的趋势结论。

## 测试重点
历史补录不造热点，转载不重复计研究，新增来源不造增长，不完整当期不报下降，低精度日期不生成精确日历。知识更新需防止并发覆盖、旧证据采纳、无权限审核及重复发布。

## 待研究结论与集成
来源适配和历史覆盖正在独立核实；价值标准等待原始文献支持；趋势权重、最低支持量与持续性门槛须通过独立对抗测试校准；首页和详情原型须先经用户确认。最终持久化沿用现有 FrontierStore 和 KnowledgeCatalog 公共接口，禁止跨模块访问内部表来绕过知识发布审核。

## 独立复核后的约束
- 月份范围与周范围相交但不能完整落入时，该来源的周比较不得宣称完整
- 同一来源时期的完整性或计数声明冲突时不择优采信
- 全局独立研究分母与来源刊载次数分别返回；转载不得提供第二个独立来源支持
- 同一研究的兼容粗细日期取交集；互斥日期和主题版本需核对
- 撤回标记优先于滞后的展示许可；无效证据引用不能使分析崩溃
- 闭合时期必须在产品时区中真正结束，结束日当天仍属开放时期

目前独立对抗场景、变换不变性及额外审查反例已纳入测试。阈值仍需真实语料校准；指标通过不代表语义结论已经经过全文评阅。
