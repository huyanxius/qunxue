# 用户长期记忆与项目记忆

用户长期记忆跨对话生效；项目记忆绑定已有 `research_tasks.task_id`，只在该用户访问该项目时生效。研究材料、编码、理论决定仍由现有模块保存，记忆不能替代研究证据。基础后端由 #344 交付，#350 增加管理页面，#361 分离保存与读取预算并修正概览复用。

## 读取、写入、维护

每轮开始，服务端读取一次当前用户及项目的短记忆快照，同时交给规划器和回答 Agent。普通回答没有额外的记忆模型调用。需要回顾旧偏好或项目决定时，Agent 可调用一次 `search_memory`；后台维护不进入主对话工具循环。

用户通过 API 人工维护条目，或在对话中明确要求记住、修改、忘记。后者由 `change_memory` 执行，工具提交成功后才能报告已保存；每轮最多三个成功变更。工具的用户及项目身份由服务端绑定，模型不能指定其他用户或项目。写工具按显式请求词预筛选，是否确属用户当前要求仍由模型按工具指令判断，不能将引文中的要求当作授权。

后台每分钟尝试领取一个任务：会话至少空闲十分钟、该用户无运行中的 Agent、存在未处理用户消息且仍有预算。每次最多处理十六条消息，只调用一次无行动工具的结构化提取模型。没有值得保留的新信息时允许返回空数组，并推进游标。失败保留预算、十五分钟后重试；同一输入最多三次，新增输入才重新获得尝试机会。五分钟租约使进程重启后的任务可恢复。

候选必须携带当前批次中真实用户消息的 ID 和逐字引文。服务端核对来源、范围、长度与版本；同一 key 按原始消息时间合并，新证据优先于后处理的旧对话。原文中的受访者、作者不等于用户；推测、研究假设和未采纳的建议不作为确定记忆。语义抽取仍可能判断失误，因此保留来源和人工纠正入口。

## 负担与容量

| 限制 | 当前值 |
| --- | --- |
| 每轮常驻记忆快照 | 1,200 UTF-8 字节，包含范围和来源类型标签 |
| 单条记忆正文 | 最多 2,000 UTF-8 字节，人工与自动记忆使用同一限制 |
| 每次按需检索 | 最多 5 条，完整 JSON 通常不超过 4,096 UTF-8 字节 |
| 每个范围活动条目 | 最多 100 条 |
| 每次后台提取输入 | 提示词和载荷合计最多 22,000 UTF-8 字节 |
| 后台输出 | 最多 1,500 tokens、8 条候选 |
| 每用户每日后台预算 | 最多 8 次、64,000 tokens；每次先预留 24,000 |

UTF-8 字节是对字节型 tokenizer 的保守上界，不使用容易低估中文的“字符数除以四”。这些限制只约束记忆部分，不代表整个 Agent 提示词长度。保存不再受每范围 400 字节限制。快照优先选入人工确认的完整条目，放不下时给出同样计入预算的检索提示；人工保护保证后台不覆盖，不保证每轮全文加载。检索按完整返回 JSON 计量；当首条命中因控制字符转义而独自超出普通预算时，只返回这一条，硬上限为 12,512 字节，避免合法原文永远无法读取。模型返回实际用量后结算后台预留额；失败或用量未知保留全部预留，因此默认配置连续未知失败最多消耗两次预留。

配置项：`QUNXUE_MEMORY_LEARNING_ENABLED`、`QUNXUE_MEMORY_LEARNING_IDLE_SECONDS`、`QUNXUE_MEMORY_LEARNING_DAILY_CALLS`、`QUNXUE_MEMORY_LEARNING_DAILY_TOKENS`。后台用现有模型端点，不新增模型依赖、向量数据库或消息队列。每个服务进程串行调度，跨进程通过数据库租约、范围版本和用户预算协调。

## 人工维护与隔离

- `GET/POST /api/memories?task_id=…`：列出或创建；创建时 `task_id` 在 JSON body。无 task_id 表示用户记忆。
- `GET/PATCH/DELETE /api/memories/{memory_id}`：查看、修改、删除；修改和删除要求 `expected_version`，冲突返回 409。
- `GET /api/memories/{memory_id}/revisions`：最近五十个版本及来源。
- `GET/PATCH /api/memories/settings?task_id=…`：分别控制前台使用与后台学习，设置也有版本检查。
- 列表同时返回 `limits.max_entries` 与 `limits.max_content_bytes`，供前端校验；可信的记忆验证原因使用标准 `error.message` 返回。
- `POST /api/memories/overview`：生成当前范围的临时阅读摘要，不写回记忆或进入 Agent 上下文。每进程缓存最多 64 个范围，按条目身份、来源与内容指纹复用；设置及同内容编辑不重算。修改/删除使旧内容失效，返回前再次核对内容。缓存因进程重启或容量淘汰而丢失时，下次读取会重新生成；没有额外数据库或常驻后台摘要任务。

所有接口要求登录并校验项目归属。创建和修改使用 `Idempotency-Key` 防重放；设置与删除采用版本检查。自动学习不得覆盖人工或用户明确保存的条目。人工修改、删除或设置变更会推进该范围的学习时间屏障，丢弃屏障前的旧来源，包括尚未首次处理的历史对话，避免旧偏好换个 key 又回来。

删除清空条目及修订历史中的内容和来源引文，留下无正文的 key 墓碑以阻止自动复活。用户要重新记录时可使用新 key。删除记忆不等于删除原始对话，已经开始的回答仍可能持有本轮旧快照；下一轮重新读取。

迁移 `20260905_0370` 增加六张表：范围及开关、条目、版本、幂等请求、后台游标/租约、用量。迁移不改写已有研究数据。#361 无新增迁移，已有记录继续有效；前端沿用记忆管理页面。

## 验证

API、来源验证、人工编辑与后台并发、删除防复活、额度公平性、失败重试、证据时序、租约恢复、PydanticAI 工具接线，以及迁移/架构和原 Agent/项目/附件回归，共 129 项通过。前端类型检查通过。真实模型验收使用独立临时数据库和测试账号，可显式运行：

```bash
QUNXUE_MEMORY_LIVE_ENV_FILE=/absolute/path/to/existing/backend/.env \
  .venv/bin/pytest tests/test_agent_memory_live.py -s
```

该测试不会在普通 CI 中联网。2026-09-05 使用现有 DeepSeek V4 Flash 配置，两项真实模型测试通过（47.97 秒）：实际 API 对话完成记住两个范围、新对话回忆、修正、忘记；后台从单条用户消息学习 APA7 偏好，保留逐字来源，对受访者原话返回空候选。该小样本证明功能链路，不代表全面的记忆质量评测，也不是生产部署验收。

真实调用还暴露并修复两处兼容边界：规划 `run_sync` 与可取消回答必须复用线程事件循环，避免已打开的模型连接跨循环失败；DeepSeek Flash 的后台结构化输出沿用现有非思考配置。真实对话首条消息序号是 0，后台初始游标为 -1，不能漏掉单轮会话。
